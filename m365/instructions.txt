# 去哪個檔找
- 畫面代號(如 CASM001)是什麼、六層檔案在哪 → 20-資料-畫面清冊(每行一支,以「[畫面 代號]」開頭),再到對應模組檔看細節。
- 某張表(如 CAS003A)被哪些畫面用、改它影響誰 → 21-資料-實體表(以「[表 表名]」開頭),再看模組檔的「跨模組共用 / 跨模組依賴」章節。
- SP / Function / Trigger / 報表範本 / Windows 服務 → 22-資料-SP報表服務。
- 使用者貼上的錯誤訊息 → 23-資料-錯誤訊息反查(以「[訊息 原文]」開頭;{…} 是程式組字串的變數部分,搜尋時用訊息中固定的片段)。
- 已知缺陷、某畫面有沒有坑 → 24-資料-已知缺陷,以及模組檔的「附錄 E」。
- 症狀排查(開不起來、資料沒進去、報表、批次、部署) → 01-導覽 檔中的 TROUBLESHOOT。
- 代號規則、部署矩陣、常用指令 → 01-導覽 檔中的 CHEATSHEET。

- 六層架構、.NET Remoting、四眼(EVA)覆核引擎、typed DataSet、畫面型別 → 03-技術架構。
- 要動手改(加欄位、加畫面、加查詢、加批次、加報表、改四眼流程、改 SP、部署、建環境) → 04-維護手冊。
- 單一模組的業務、資料模型、畫面清冊、逐畫面卡控 → 10~16 模組檔(檔名列出所含模組;OFD 拆成 OFD1~9、OFDB 批次、OFDI 查詢、OFDR 報表多片)。

# 背景速記
- 畫面代號 = 前 3 碼模組 + 第 4 碼型別(M 維護 / I 查詢 / B 批次 / R 報表)+ 3 碼流水號 + 可選後綴。六層檔名由代號推導:UI.<MOD>/<代號>.cs → FormProxy.<MOD>/<代號>_Pxy.cs → Control.<MOD>/<代號>_Ctl.cs → PO.<MOD>/<代號>_PO.cs → <代號>Model.xsd(DataEntity)/ <代號>View.xsd(UIEntity)。
- 代號的 A / B 後綴成因至少七種,不能套規則,要逐支查。
- 四眼(EVA)= Entry(經辦鍵入)→ Verify(覆核)→ Approve(核准)三階段;核准前資料在待辦裡,不算正式資料。細節在 03-技術架構 §3、01-導覽 CHEATSHEET §4。
